## 1. このカテゴリが既存9カテゴリと違う点

### 1-1. 判定が窓でも系列でもなく、完全一致であること

（**この節は MS3749 14件だけが登録されていた時点の読み取りです。**
現在の `gate` は、ここに書いた3点に加えて応答時間の条件を持ちます。
条件が4つになった経緯と、追加された条件だけが非対称であることは 9-2 にあります。）

`src/categories/insulation.mjs` の `gate` は、次の3点の**一致**だけを要求します。

- `specs.inputSignal`（入力信号）が一致すること
- `specs.output1Signal`（第1出力）が一致すること
- `specs.output2Signal`（第2出力）は、**両方が持つときだけ**一致すること。
  両方とも持たない（1出力型どうし）なら判定材料にせず通す。
  片方だけが持つ組は候補にしない

他の9カテゴリの `gate` と並べると違いがはっきりします。

| カテゴリ | 判定の軸 | 該当コード |
|---|---|---|
| 電磁接触器・電磁開閉器 | 定格使用電流の**窓**（`withinWindow` ±30%）＋後継品バイパス | `src/categories/contactor.mjs` |
| サーマルリレー | 設定電流範囲の**重なり**（`rangeOverlap`）＋後継品バイパス | `src/categories/thermal.mjs` |
| インバータ・サーボ | 電圧クラス／電源相数の一致＋定格の**窓**＋後継品バイパス | `src/categories/drive.mjs` |
| センサー4種 | 出力極性・配線本数＋**互換系列**（`compatKey` / `compatGroup`）＋後継品バイパス | `src/categories/sensor-common.mjs` |
| **絶縁変換器** | **信号種別の完全一致のみ**（窓なし・系列なし・後継品バイパスなし） | `src/categories/insulation.mjs` |

（この表の絶縁変換器の行も、MS3749 14件だけの時点のものです。現在は
「信号種別の完全一致＋応答時間が基準以下」で、**後者だけが向きのある条件**です（9-2）。
窓を使わない・系列を使わない・後継品バイパスを持たないことは今も変わりません。）

窓を使わない理由はコメントに書かれています。判定材料が容量ではなく**信号の種別**で、
「無電圧接点・オープンコレクタ」と「ラインドライバ」のあいだに大小が無いためです。
順序が無いものに `numericStanding` を当てると、比較できない組を無理やり2値に倒すことになるので、
`primaryStanding` は `null` を返し、`standingNote`（大小の注意書き）も持ちません。

**この点を守っている検査（`smoke`）**

- `MS3749-A-O25 の③に MS3749-A-O22 が候補として出ない（第2出力の種別が違う）`
- `MS3749-A-O22 の③に MS3749-A-O25 が候補として出ない（逆向きでも同じ）`
- `MS3749-A-D44/H の③が0件になる（第2出力を一方だけが持つ組を候補にしない）`
- `絶縁変換器の0件パネルが必要条件（入力信号・出力信号・第2出力・応答時間）を名乗る`
  … 執筆時は `絶縁変換器の0件パネルが必要条件（入力信号・第1出力・第2出力）を名乗る`
  でした。`gate` に応答時間が入り、0件パネルの文面も追随したので検査名が変わっています（9-2）

この2件（`MS3749-A-O22` / `MS3749-A-O25`）は、入力信号・第1出力・外形寸法・電源が同一で
違うのは第2出力だけなので、`gate` が第2出力を見ていなければ必ず互いの候補No.1になります。
**両方向を見る**のは、片方向だけの検査では `gate` が非対称に壊れたときに素通りするためです
（`test-compat` の対称性検査と同じ考え方だとコメントにあります）。

### 1-2. 型式コードから仕様が決まること。登録するのは実在が確認できたものだけであること

MS3749 の型式は、公式資料には**型式コード表の組み合わせとしてしか存在せず**、
個別型式としての列挙がありません（`insulation.mjs` 冒頭、および全14件の
`evidence.model.srcNote`）。したがって

- **仕様**は型式コード表から一意に決まる（電源・入力・第1出力・第2出力・オプション）
- **実在**の根拠は資料の外（現場写真・社内予備品リスト）にしかない

という、他カテゴリに無いねじれがあります。ここから
「**型式コードから組み合わせを展開して増やさないこと**」という約束が来ています
（`insulation.mjs` 冒頭に太字で書かれ、PR #29 のコミットメッセージにも
「型式コードから組み合わせを展開して増やしていない」とあります）。

執筆時の登録は14件で、`data/insulation.json` の実データは次のとおりでした
（**現在の62件のうち MS3749 の14件の分です。** 渡辺電機工業 WVP / WGP の値は 9-1 / 9-2）。

| 欄 | 実データに現れる値 |
|---|---|
| 入力信号 | 無電圧接点・オープンコレクタ ／ DC電圧パルス ／ ラインドライバ・パルス |
| 第1出力 | オープンコレクタ ／ 電圧パルス10V ／ 電圧パルス12V |
| 第2出力 | オープンコレクタ ／ 電圧パルス10V ／ 電圧パルス12V ／ ラインドライバ・パルス ／ （キーごと不在＝4件） |
| 電源電圧 | AC100〜240V ／ DC24V |
| オプション | `/H` ポリウレタン系コーティング ／ `/D` センサ供給電源 12V DC（±10%）3線式 |

**組み合わせの総数について。** 依頼では「3888通り」とされていますが、
**この数はコード・検査・データ・コミットメッセージのいずれにも現れません**
（`grep -rn "3888"` で0件）。型式コード表そのものはリポジトリに入っておらず、
`srcNote` に読み下されている範囲（オプション表が9種あることは
`tools/verify-data.mjs` の `option` の検査のコメントに書かれています）からは
総数を再現できません。よってこの文書には総数を書きません（→ 7章）。
**読み取れるのは「組み合わせとしてしか存在しない」「実在が確認できたものだけを登録する」
という扱いの方**です。

**この点を守っている検査（`verify-data`）**

- `追加レコードの規約` … 移行元に対応が無いレコード（絶縁変換器は14件すべてが該当）に
  `modelStatus: "catalog-confirmed"`、`evidence.model.state === "verified"`、
  `evidence.model` に `srcUrl` か `srcNote` のいずれかがあることを要求します。
  **出典の無いレコードは人手のレビューを待たずにここで落ちます。**
  同じ検査が、宣言に無い `specs` のキーとトップレベルキーも落とします。
- `evidence が3側面そろい、状態が3値のいずれか` … 14件とも
  `model` / `dims` / `specs` の3側面を持ち、状態が3値のいずれかであること。

**件数を固定している検査（`smoke`）**

- `絶縁変換器が62件で表示される（MTT MS3749 14件 + 渡辺電機工業 WVP 39件・WGP 9件）`
  … 執筆時は `絶縁変換器が14件で表示される` でした。データを足すたびに検査名の数が
  更新されています（14 → 39 → 53 → 62。PR #40・#41・#43 のコミットメッセージ）
- `絶縁変換器のカテゴリチップが出る`

「型式コードから展開して増やしていないこと」そのものを見る検査はありません。
増やせばこの件数の検査が落ちますが、これは件数の固定であって
「展開でないこと」の証明にはなりません。出典の要求（`追加レコードの規約`）が、
機械的に効く歯止めです。

### 1-3. 出典が2系統（実在＝現場写真／予備品リスト、仕様＝メーカー仕様書）

`data/insulation.json` の `evidence` は側面ごとに出典が分かれています。

| 側面 | 出典 | 件数（実データ） |
|---|---|---|
| `model`（実在） | 現場写真（依頼者撮影の制御盤内銘板、2026-08） | 2件（`MS3749-A-O22` / `MS3749-A-O25`） |
| `model`（実在） | 社内予備品リスト（依頼者の勤務先の予備品管理システム画面、2026-08） | 12件 |
| `dims`（寸法） | MTT 標準仕様書 MS3749（MQDDK-110729-33 Rev.2.10）p.2「外形寸法」 | 14件（`srcUrl` は同一PDF） |
| `specs`（仕様） | 同 仕様書 p.1 型式コード表・p.2 最大出力周波数ほか | 14件（`srcUrl` は同一PDF） |

**現在の62件でも、側面ごとに出典が分かれる形は変わりません。** 実データを数えると、
`model` の出典は現場写真2件（MS3749）・社内予備品リスト60件（MS3749 12件・WVP 39件・
WGP 9件）で、`dims` と `specs` はメーカー資料です。渡辺電機工業の資料は機種ごとに
分かれていて、`srcNote` に資料名まで書いてあります（9-1）。
**`srcUrl` を持つのは `dims` / `specs` とも MS3749 の14件だけ**で、
WVP 39件・WGP 9件は資料をスクリーンショットで受け取ったため `srcUrl` を持ちません
（`insulation.mjs`。実データでも `srcUrl` の保有は `model` 0件・`dims` 14件・`specs` 14件）。

**`model` には `srcUrl` が1件もありません。** 実在の根拠がWeb上の資料ではなく
写真と社内システムの画面だからで、`追加レコードの規約` が
`srcUrl` **または** `srcNote` を要求する形になっているのはこのためです
（`ADDED_RECORD_RULES.sourceKeys`）。

既登録2件の仕様の出典は、PR #33 で Rev.2.00 から Rev.2.10 へ更新されました。
理由は「現に取得できる版を指すべき」で、**仕様値は1つも変えていません**
（`insulation.mjs` 冒頭とコミットメッセージ）。

**この点を守っている検査**

- `verify-data` の `追加レコードの規約` … 出典キーの存在と `evidence.model.state` を見ます。
- `verify-data` の `evidence が3側面そろい、状態が3値のいずれか` … 側面が欠けたら落ちます。
- `smoke` の `②の出典行の検査が、本文を持つレコードと持たないレコードの両方を通っている`
  … `MS3749-A-O25` を「出典の本文あり」側の足場に使い、本文（`srcNote`）とリンク（`srcUrl`）が
  実際に描かれていることを見ます。

ただし、**「`model` は写真／リスト、`dims` と `specs` は仕様書」という2系統の分かれ方を
機械的に照合する検査はありません。** 側面ごとに別の出典を持てること自体は
`evidence` の構造が保証しますが、どの側面がどの系統を指すかはデータの書き方に依存します（→ 7章）。

### 1-4. 型式に現れず、現場で決まる設定があること（極性反転スイッチ）

MS3749 の全14件の `note` に、次の趣旨が入っています
（**`note` を持つのはいまも MS3749 の14件だけ**です。実データで確認：62件中14件。
WVP・WGP で `note` をキーごと不在にした理由は 9-6 の表に引いてあります）。

> 極性反転スイッチ（POLARITY N / R）が前面にある。型式コードに現れないので、
> 設定は現物で確認すること（仕様書 p.2「出力論理」）。

**型式が一致しても出力波形の極性は決まらない**、という意味で、
このカテゴリの「完全一致で候補を出す」判定の外側に残る条件です。
`gate` はこれを見ません（データに持っていないので見られません）。
だから現場向けの注意として `note` に置かれています。

PR #30 は、この `note` を「交換作業で現場が知る必要があること」だけに絞り、
未登録の理由（取付穴ピッチ・入力抵抗・TIA/EIA-422-B 準拠）を
その項目の出典を持つ側面（`evidence.dims.srcNote` / `evidence.specs.srcNote`）へ移しました。
②画面の `note` は型式名の直下に出るため、長いと現場が読むべき1点が埋もれるからです
（実測 375px 幅で `MS3749-A-O25` が11行→6行、`MS3749-A-O22` が9行→4行）。

**この点を守っている検査は、絶縁変換器を名指ししたものがありません。**
`smoke` の `デバイスの note が実際に描画される` は電磁接触器の `HC35` を足場にしており、
絶縁変換器の `note` に極性反転スイッチの記述があることを見る検査はありません（→ 7章）。

## 2. データ構造の約束

`specs` のキーは `tools/schema-map.mjs` の `ADDED_SPEC_KEYS.insulation` に7つ宣言されています
（`inputSignal` / `output1Signal` / `output2Signal` / `output1MaxFreqHz` /
`output2MaxFreqHz` / `powerSupply` / `option`）。移行元の3アプリに存在しないカテゴリなので、
7キーすべてがここの宣言になります。宣言に無いキーは `追加レコードの規約` で落ちます。

**現在の宣言は11キーです。** 渡辺電機工業の WVP / WGP を足したときに
`inputResistance` / `outputSignal` / `outputLoad` / `responseUs` の4キーが増えました
（PR #40 の `3b5c06b` が `tools/schema-map.mjs` を変更しています）。
62件でのキーの保有件数は実データを数えると次のとおりで、
**キーはレコードによって変わります**（同じ意味でないものを同じキーに寄せていない）。

| キー | 保有件数 | 持つ系列 |
|---|---|---|
| `inputSignal` | 62 | 全件 |
| `powerSupply` | 62 | 全件 |
| `output1Signal` / `output1MaxFreqHz` | 14 | MS3749 |
| `output2Signal` / `output2MaxFreqHz` | 10 | MS3749（第2出力を持つもの） |
| `option` | 9 | MS3749 |
| `inputResistance` / `outputSignal` / `outputLoad` / `responseUs` | 48 | WVP 39・WGP 9 |

### 2-1. `output1Signal` / `output2Signal` を別キーにした理由

集合（配列）で持つと、**第1出力・第2出力の位置情報が失われる**ためです
（`schema-map.mjs` の該当コメント）。

- 現場は端子番号で配線する。仕様書 p.2 の端子配置図でも第1出力は端子④⑤、
  第2出力は⑥⑦⑧と物理的に分かれている
- どちらの出力かは判定にも直結する（`gate` は第1出力と第2出力を別に扱い、
  第2出力だけ「両方が持つときだけ一致を要求する」という別の規則を当てている）

配列 `[…]` で持っていたら、この2つを区別して判定に掛けることはできません。

周波数を `output1MaxFreqHz` / `output2MaxFreqHz` と Hz の整数で持つのは、
**キー名だけで物理量と単位が決まるようにする**ためです（`README.md`「データの約束」）。
表示の kHz 換算はカテゴリ側の `formatFreq` が行います。

### 2-2. `option` を配列にし、`code` と `text` の組で持つ理由

- **配列にする理由** … `option` は型式コード末尾の `／□` で、
  **複数指定できる**（仕様書の発注例 `MS3749-A-D11/AT`）。単一の値では表せません。
- **`{ code, text }` の2つ組にする理由** … `code` だけでは現場に伝わりません。
  画面に「H」とだけ出ても、それがコーティングなのかセンサ供給電源なのかが読めない。
  型式の末尾に現れる綴り（`/H`）と、仕様書 p.1 のオプション表の文言を必ず並べて出します
  （`optionText` は `` `/${o.code} ${o.text}` `` を作ります）。

**この点を守っている検査（`verify-data`）**

- `option は配列で、各要素が code と text を持つ` … 配列であること、要素がオブジェクトであること、
  `code` と `text` が**非空文字列**であること、宣言に無いキーを持たないこと。
  `text` が欠けたときのメッセージには
  「code だけでは画面に「H」とだけ出て現場に伝わらない」と理由が入っています。
- **保有0件なら検査失敗**にしてあります（対象0件のまま PASS しないため。
  `verify-legacy` 検査1 が塞いだ穴と同じ形）。

`code` の許可値は検査に書かれていません。仕様書のオプション表は9種ありますが
登録があるのは `H` と `D` の2種だけで、残り7種を宣言に書くと
**データに無いものの文言を検査側で二重管理する**ことになるためです
（`tools/smoke.mjs` が色をテーマから読むのと同じ考え方だとコメントにあります）。

### 2-3. 第2出力を持たない型式で、キーごと不在にする扱い

型式コードの第2出力には「未記入：なし」があります。
その型式は `output2Signal` と `output2MaxFreqHz` を**キーごと落とします**。
空文字・`"なし"`・`0` で埋めません（`README.md`「データの約束」の0番兵の禁止と同じ）。
実データでは4件（`MS3749-A-D4/H` / `-A-D3/H` / `-A-L2/H` / `-A-O2/H`）がこの形です。

`option` も同じで、**空配列で持たせません**。理由は表示側の分岐にあります。
空配列は `formatSpecValue` の `v == null` に掛からないため「―」にならず、
`summary` 側も `length` で判断しているので、
「持たない」と「持つが空」が画面で見分けられなくなります。

**この点を守っている検査**

- `verify-data` の `option を空配列で持たない（キーごと不在か、1件以上）`
  … こちらも保有0件なら検査失敗にしてあります。
- `smoke` の `MS3749-A-D4/H の②に第2出力の欄が出ない（1出力型・MS3749-A-O25 では出る）`
  … ラベルの**前方一致**で見るのは「第2出力」と「第2出力 最大周波数」の2欄をまとめて
  落とすためです。空振り防止に、第2出力を持つ `MS3749-A-O25` では同じ欄が出ていることも
  併せて見ます（欄の描画ごと壊れたら両方が落ちます）。
- `smoke` の `MS3749-A-O25（option なし）の②にオプションの欄が出ない`
  … 同じ画面が仕様欄を描いていること（第1出力の欄がある）も併せて見ます。

### 2-4. `signalMatch` が「片方でもキーを持たなければ false」を返す理由

```js
function signalMatch(a, b) {
  if (typeof a !== 'string' || typeof b !== 'string') return false;
  return a === b;
}
```

**値が無い側を「一致」に倒さないため**です。`a === b` だけで書くと
`undefined === undefined` が真になり、
「どちらも入力信号を登録していないから一致」という**根拠の無い候補が静かに混ざります**。
`CLAUDE.md` の「『解析できないから一致とみなす』経路を作らない」がここに効いています。

第2出力の「両方とも持たない」＝1出力型どうしは、これとは別に `gate` 側で扱います
（`a2 == null && m2 == null` なら `true` を返して通す）。
**同じ「両方とも無い」でも、意味が違うので置き場所を分けています。**
入力信号・第1出力は型式コード上かならず指定される（＝必ず存在する）ので、
無いのはデータの欠落。第2出力の不在は「なし」という仕様です。

## 3. 表示の約束

### 3-1. 信号名を銘板の表記で表示すること

`formatSignal` が、表示のときだけ信号名を銘板の印字へ置き換えます。
**データは変えません。**

| データの値（仕様書 p.1 の表記） | 表示（銘板の印字） |
|---|---|
| 無電圧接点・オープンコレクタ | `OPN.C.` |
| オープンコレクタ | `OPN.C.` |
| ラインドライバ・パルス | `Line Driver Pulse` |

**データ側を銘板の綴りに書き換えない理由** … `specs` の出典は仕様書
（MQDDK-110729-33 Rev.2.10）だからです。写真でしか確認していない綴りで仕様書由来の値を
上書きすると、出典と値が食い違ったまま残ります。
`output1MaxFreqHz` が `100000` を持ったまま `formatFreq` で `100kHz` と出すのと同じ形です。

**変換表に載っているのが3語だけである理由** … 銘板の写真で実際に読めたのがこの3つだけだからです。
出典は依頼者撮影の現場写真（制御盤内銘板、2026-08）で、`MS3749-A-O25` と `MS3749-A-O22` の銘板に
`IN OPN.C.` / `OUT1 OPN.C.` / `OUT2 Line Driver Pulse` と印字されていました。
DC電圧パルス・電圧パルス10V・電圧パルス12V は銘板を確認していないので入れていません。
コメントはその危険をこう書いています——「OPN.C. があるなら電圧パルスも略記だろう」と埋めた瞬間、
画面に出るのは**現物のどこにも無い綴り**になり、照合の役に立たないどころか
銘板と突き合わせた人を迷わせる。

`formatSignal` は**表に無い値をそのまま返します**。空文字や「―」に倒すと、
登録されている値が画面から消えるためです（変換できないことは、変換しないことで表す）。

**変換の直接の動機（PR #34）** … ③の候補カード右上（`.card-right`）は主スペックの幅で決まり、
`flex-shrink:0` なので縮みません。主スペックが「無電圧接点・オープンコレクタ」（全角14字）の
ときは 212.5px になり、左列だけが削られて 390px 幅で型式名 `MS3749-A-O25/H` が2行に
折り返していました。銘板の印字にすると 54px / 1行になります（いずれも実測値）。

**この点を守っている検査（`smoke`）**

- `MS3749-A-O25 の②で第2出力が Line Driver Pulse になる（銘板の印字）`
- `MS3749-A-O25 の②で入力信号・第1出力が OPN.C. になる（同じ画面で表記が割れない）`
  … 3つに同じ `format` を掛けていることを固定します。1つだけ略記にすると同じ仕様欄で表記が割れます。
- `MS3749-A-D4/H の②で第1出力が「電圧パルス12V」のまま（変換表に無い値はそのまま出す）`
  … 未知の値を握りつぶさないこと。`formatSignal` が表に無い値を空文字や「―」に倒す実装に
  なると登録済みの値が画面から消えますが、`MS3749-A-O25` 側の検査だけでは落ちません。
- `MS3749-A-O25 の③のカード右上が OPN.C. になる（MS3749-A-O25/H を含む）`
- `MS3749-A-O25 の③で型式名が1行に収まる（画面幅 390px・MS3749-A-O25/H を含む）`
  … 折り返しの境目は全角13字と14字のあいだにあり、差は約2文字分しかありません。
  この検査が無いと、変換表から `MS3749-A-O25` の値を外しても全検査が通ります。

### 3-2. 「信号名の表記」の行を、変換が起きた型式にだけ出す理由

`nameplateNote` が②の仕様欄の最後に、銘板の印字と仕様書の表記の対応を1行足します。

- **なぜ足すのか** … 「OPN.C.」は仕様書のどのページにも出てこない綴りなので、
  **仕様書だけを持っている人が照合できなくなります。** 型式コード表の
  「無電圧接点・オープンコレクタ」と結び付ける手がかりが画面から消えるためです。
- **なぜ欄の値を「OPN.C.（無電圧接点・オープンコレクタ）」と併記にしないのか**
  … 同じ `format` が③の候補カード右上にも掛かり、3-1 で短くした意味が消えるためです。
- **なぜ欄ごとに書くのか** … `OPN.C.` が仕様書の2つの表記（入力側「無電圧接点・オープン
  コレクタ」／出力側「オープンコレクタ」）に対応するためです。まとめて書くと
  どちらの欄がどちらなのかを言えません。
- **なぜ変換が1つも起きていない型式では行ごと返さないのか**
  … `MS3749-A-D4/H` のように銘板を確認していない値しか持たない型式にこの行を出すと、
  **仕様書の表記のまま出している値まで「銘板の印字」と名乗る**ことになります。
  持たないものは行ごと返さないという、第2出力・オプションと同じ扱いです。

**この点を守っている検査（`smoke`）**

- `②が銘板表記であることを名乗る（MS3749-A-O25 に対応表・MS3749-A-D4/H には出ない）`
  … 対応3組が本文に出ることと、`MS3749-A-D4/H` に「信号名の表記」ラベルが**無い**ことを
  同じ検査で見ます。両側を見るので、行を常時出す実装でも常時出さない実装でも落ちます。

### 3-3. 第2出力・電源電圧・オプションを `specDefs` ではなく `summary` に置いた理由と、その代償

`specDefs` に宣言してあるのは**全件が必ず持つスペックだけ**です。
執筆時の宣言は `inputSignal` / `output1Signal` / `output1MaxFreqHz` の3つでした。

**現在の宣言は `inputSignal` ひとつです。** WVP は出力が1系統で、応答の速さを
最大出力周波数ではなく応答時間で語るため、第1出力・第1出力 最大周波数は
「全件が持つ」ではなくなりました。宣言に残したままだと WVP・WGP 48件の②に
「第1出力 ―」「第1出力 最大周波数 ―」が並ぶので、この2つは `summary` へ移してあります
（PR #40 のコミットメッセージと `specDefs` の JSDoc。**②の欄の並びは `summary` 側で
保っているので、MS3749 側の画面の見え方は変わっていません**）。
理由づけは下に書いた「値の有無に関わらず必ず描く」と同じもので、
**同じ理由が2度目に効いた**形です。下の「代償」も、宣言が1つになったぶん強く効きます。

（②の仕様欄の話です。**③の候補カードで電源電圧をどう出すかは 8章**。②の欄はそのままです。）

**理由** … `src/core/ui.mjs` の `specGrid` は、宣言された `specDefs` を
**値の有無に関わらず必ず描きます。** 型式によって有無が変わるスペックをそこに置くと、
持たない型式の画面に「第2出力 ―」という欄が残ります。1出力型に対して、
この「―」は**「該当なし」なのか「未登録」なのかを語れません。**
有無が変わるもの（第2出力・第2出力 最大周波数・オプション）は `summary` に置き、
持たない型式では欄そのものを出しません。電源電圧も `summary` 側にあります。

**並び順** … `specDefs` の宣言順は「人が見分けやすい順」で、銘板の印字（IN / OUT1）と
型式コードの並び（電源・入力・第1出力）に沿っています。`summary` はその続き
（第2出力 → 第2出力 最大周波数 → 電源電圧 → オプション → 信号名の表記）を描くので、
②の仕様欄は上から銘板の並びのまま読めます。対応表（3-2）が最後なのは、
個々の値を読んだあとに「どの表記で出しているのか」を置くためです。

**代償** … 曖昧一致リストの識別材料は `src/core/registry.mjs` の `distinguishingSpec` が
**`specDefs` の宣言順の先頭から「値が割れている最初のスペック」を選ぶ**ため、
`specDefs` から外した第2出力・電源電圧・オプションは**識別材料に選ばれません。**

いま登録されている62件に `normLoose`（空白・ハイフン・小数点を落とした綴り）で
同じ綴りになる組は無く（実データで確認：衝突0組。執筆時の14件でも0組）、
曖昧一致リストにこの4件が並ぶ経路はありません。
将来そういう組が入ったときは、`verify-data` の
`検索で同じ綴りになる型式に見分ける材料がある` が**黙って通らずに落ちます**。
この検査は「割れているスペックがあるか、メーカーが違うか」を要求するので、
`specDefs` に残した3つがすべて同値の組が入れば失敗します。
そこで宣言を見直すこと、とコメントは指示しています。

### 3-4. 主スペックに `inputSignal` を使っていること

`specDefs` の `inputSignal` に `primary: true` が付いています。
カード右上（`.card-right .primary-spec`）とヘッダに出るのはこの値です。
コメントは理由を「置換えの可否をいちばん左右するのが『その信号を受けられるか』だから」とし、
**「暫定で入力信号」**と書いています。

**ただし、判定で一致を要求する値なので、候補の見分けには使えません。**
`gate` が `inputSignal` の一致を必要条件にしている以上、③に並ぶ候補は全件が
基準機と同じ入力信号を持ちます。カード右上は全件同じ文字列になります。
実際、`smoke` の `MS3749-A-O25 の③のカード右上が OPN.C. になる（MS3749-A-O25/H を含む）` は
**候補全件が同じ値であること**（`every`）を検査として固定しています。
これは折り返し対策の足場ですが、同時に「主スペックが候補を見分けないこと」の実測でもあります。

他カテゴリはこの2つを分けています。`registry.mjs` の `distinguishingSpec` のコメントは
「宣言順は『見分けやすさ』を表すので、判定に使う主スペック（`primary`）が先頭とはかぎらない。
インバータは判定を定格出力電流で行いつつ、識別材料には適用モータ容量を先に出す」と書き、
`test-compat` に `判定に使う主スペックは定格出力電流` と
`曖昧一致リストの識別材料は適用モータ容量（銘板から即断できるほう）` の2検査があります。
絶縁変換器では、`specDefs` の2番目以降（第1出力・第1出力 最大周波数）が識別材料の候補になります。

（**現在は `specDefs` の宣言が `inputSignal` ひとつだけになりました**（3-3）。
2番目以降が無くなったので、いまこのカテゴリで識別材料になり得るのは入力信号だけです
——それは `gate` が一致を要求する値なので、**候補を見分けません**。
`specDefs` の JSDoc も同じことを書いています。62件に `normLoose` で同じ綴りになる組が
無いため曖昧一致リストが並ぶ経路そのものが無く、この状態でも画面には出ません。）

なお、③で候補どうしの差を読ませる役は `detailPanels`（オプション欄）が持っています（4-1）。

## 4. 意図的にやらないと決めたこと

いずれも `src/categories/insulation.mjs` と `tools/schema-map.mjs` のコメント、
および PR #29・#33 のコミットメッセージから読み取れる範囲です。

### 4-1. `option` を判定（`gate`）に使わない

`/A`〜`/F` のセンサ供給電源は2線式・3線式センサへ電源を供給する機能で、
入出力の能力そのものにあたります。**供給型が必要な回路に非供給型を付ければセンサが動かない**ので、
本来は判定材料になり得ます。それでも入れない理由が3つ挙がっています。

1. 該当が1件（`MS3749-A-D33/D`）しかなく、**判定の正しさを検査で固定できない**。
   （執筆時は「14件中1件」。62件になった現在も、`insulation.mjs` のコメントは
   「62件中1件」でこの1件のままです）
   候補が0件のまま「PASS」と出る検査になる（`CLAUDE.md` が禁じている形）
2. `/A`〜`/F` の6種が揃うまで、どれとどれが代替可能かを決められない。
   24V と 12V、2線式と3線式は互換ではない
3. 表示があれば現場は画面で気づける。②の仕様欄と③の候補カードの両方に出している

**該当データが増えた時点で再検討すること**、とコメントは明示しています。
判定に入れるなら「コーティング（`/H`）は違っても置換えできる」
「センサ供給電源は違うと使えない」のように**オプションの種別ごとに扱いが変わる**ので、
`option` の一致では書けない、とも書かれています。

判定に入れない代わりに、③の候補カードに `detailPanels` でオプション欄を出しています。
`gate` に入れていない＝**オプションが違っていても候補として並ぶ**ので、
違いを言わなければ現場は「型式が違うだけの同じもの」として受け取ります。
`MS3749-A-O25` と `MS3749-A-O25/H` は仕様値が1つも違わず差はオプションだけなので、
出さなければ画面上は完全に同じ2枚のカードになります。

パネルの決め方も理由付きで書かれています。

- 出すのは事実（候補は何を持つか／基準機は何を持つか）までで、**置換えの可否は書かない**。
  コーティングの有無が問題になるかは設置環境で決まり、センサ供給電源が要るかは
  接続先のセンサで決まる。どちらもアプリは知らない
- 枠の色は、**基準機が持つオプションを候補が持たないときだけ橙（`warn`）**。
  「失う側」は同じ重みで扱えないため。逆に候補側にだけ付いている分は `info`
- どちらもオプションを持たない組では枠を出さない（`MS3749-A-D45` ⇔ `MS3749-D-D45` がこれ）。
  「オプションなし ⇔ オプションなし」の枠は情報を増やさず、本当に差がある枠と同じ場所を占める

**この点を守っている検査（`smoke`）**

- `MS3749-A-O25 の③に MS3749-A-O25/H が候補として出る（差はオプションだけ）`
- `MS3749-A-O25/H の候補カードに「ポリウレタン系コーティング」が出る（code だけでは伝わらない）`
- `MS3749-A-D33/D の②のオプション欄に「センサ供給電源 12V DC（±10%）3線式」が出る`

**電源電圧（`specs.powerSupply`）も同じ形です。** `gate` に入れていないので
電源電圧が違っていても候補に並びます。③にパネルを出したのは後のPRで、
判断は 8章にあります（`option` を `gate` に入れない理由とは別の理由です）。

### 4-2. センサ供給電源を判定に使わない

4-1 の一部です（`/A`〜`/F` はオプションとして登録されるため）。
`option` を `gate` に入れない判断がそのまま効いており、**センサ供給電源だけを別枠で
判定に入れる経路はありません。** 0件パネルの文面がオプションを名指ししていないのも同じ理由で、
「`gate` が見ていない条件を0件の理由として名乗らない」ためです（→ 4-6）。

### 4-3. 出力の入れ替え判定（OUT1 と OUT2 が入れ替わった機器）を実装していない

依頼者からの要求があり、PR #29 でも PR #33 でも実装されていません。
`gate` のコメントに、次にこの `gate` を触る人へ向けた4点が残っています。

1. これは判定の意味を「そのまま挿せる」から「配線を直せば使える」へ**広げる変更**になる。
   いまの候補は前者だけを指している
2. MS3749 では第1出力にラインドライバを選べない（型式コードの第1出力は 1〜4 のみで、
   5＝ラインドライバ・パルスは第2出力専用）。つまり「OUT1 がラインドライバ、
   OUT2 がオープンコレクタ」という入れ替え品は同シリーズ内に存在せず、
   **いま実装しても対象は0件**。追加した12件でも第1出力にラインドライバを持つ型式は1件も無く、
   対象は依然0件のまま（実データでも第1出力は
   オープンコレクタ／電圧パルス10V／電圧パルス12V の3種のみ）
3. 端子割付が出力種別で変わる。第2出力がラインドライバのときは端子⑥⑦⑧が Y / Z / COM になる
   （仕様書 p.2）。入れ替えは盤内の配線変更を伴うので、
   「候補に出す」と「そのまま置換えられる」が一致しない
4. 応答周波数が出力種別で違う（オープンコレクタ 100kHz / ラインドライバ 200kHz）。
   入れ替えの可否は種別だけでなく周波数まで見ないと決まらない

実装するなら**完全一致の候補とは別ゾーンに分け、配線変更が要ることを明示すること**
（③の2分割＝`zoneHead` が前例）。同じ列に混ぜると、そのまま挿せる候補と見分けがつかなくなります。

### 4-4. 在庫数を持たない

追加12件の実在の根拠は社内予備品リストで、そこには**現在庫が載っています。**
それでもデータに持ちません。理由はコメントにこう書かれています。

> 変動する値なので持たない。「棚にある」は復旧時間に直結する情報だが、
> データに持つと腐る。持つとしたら「予備品として登録された実績がある」という
> 事実にとどめる形。**判断は保留**

「持たない」と決め切ったのではなく、**別の形で持つ可能性を残した保留**である点が
他の「やらない」と違います。

### 4-5. 後継品バイパス（`a.id === m.successorId`）を `gate` に置いていない

他の9カテゴリの `gate` は、いずれも冒頭で「メーカー公表の後継品は無条件で候補」という
バイパスを持っています（`contactor.mjs` の `baseGate`、`thermal.mjs`、`drive.mjs` 2箇所、
`sensor-common.mjs` の `sensorGate`）。絶縁変換器だけが持ちません。

理由は、生産終了・後継の情報を MTT について調べておらず、
`data/insulation.json` に `successorId` を持つレコードが1件も無い（実データで確認：0件）ため、
**いま書いても一度も通らない経路になる**からです。
「後継指定なら信号種別が違っても候補に出してよいか」は、
**実例が出てからその実例と一緒に決める**、とコメントは書いています。

`verify-data` の `successorId と mountsOn が解決する` は存在しますが、
絶縁変換器には対象がありません。

## 6. 失敗の記録

**同じ形の失敗が2回起きています。両方とも「画面全体の文字列を見る検査」でした。**

### 6-1. 1回目：`option` の `text` を落としても検査が通った（PR #33 `4dbfed9`）

②のオプション欄の検査が「センサ供給電源 12V DC（±10%）3線式」という文字列を
`textContent('#app')`（画面全体）から探していました。

`option` の `text` を落として `code` だけにする**壊し方をしても検査は通りました。**
同じ語が `evidence.specs.srcNote`（型式コードの読み下し）に出ていたためです。

### 6-2. 2回目：「②に第2出力が出る」も同じ形だった（PR #34 `d20e4f3`）

「②に第2出力（ラインドライバ・パルス）が出る」も `#app` 全体の文字列で見ていました。
この書き方は**表示を銘板表記（`Line Driver Pulse`）に変えても落ちません。**
`note`（「第2出力がラインドライバ・パルスのため…」）と
`evidence.specs.srcNote`（型式コードの読み下し）に同じ語があるので、
**仕様欄が何を出していようと通ってしまいます。**

### 6-3. なぜこのカテゴリで繰り返し起きるのか

**このカテゴリは `srcNote` に型式コードの読み下しを書きます。**

> MS3749 Rev.2.10 p.1 型式コード表（A＝AC100〜240V／D＝DC電圧パルス／3＝電圧パルス10V／
> 第2出力 3＝電圧パルス10V／D＝センサ供給電源 12V DC（±10%）3線式）…

読み下しは、仕様欄に出る文言をそのまま含みます。つまり
**仕様欄の文言はほぼ必ず出典行にも現れます。**
加えて PR #30 以降も `note` には端子割付など仕様の語が残っています。
したがって、このカテゴリで**画面全体の文字列を見る検査は空振りします。**
値を落としても、表記を変えても、出典行が同じ語を出しているので通ってしまいます。

### 6-4. どちらも「欄から読む形」に直した。直し方

②の仕様欄を**ラベル → 値の組**で DOM 順のまま拾い、見たい欄の**値そのもの**を突き合わせます。

```js
async function confirmSpecRows() {
  return page.$$eval('#app .grid .spec', (els) => els.map((e) => [
    e.querySelector('.l').textContent.trim(), e.querySelector('.v').textContent.trim(),
  ]));
}
```

`insulationResult(model)` がこの組を保持し、`specOf(label)` で欄の値を、
`labels` で欄の有無を返します。検査はこの2つだけを見ます。

| 見たいこと | 直す前 | 直した後 |
|---|---|---|
| 値が出ているか | `textContent('#app').includes(値)` | `specOf('オプション')?.includes(値)` / `specOf('第2出力') === 'Line Driver Pulse'` |
| 欄が無いこと | （書けない） | `!labels.includes('オプション')` / `!labels.some((l) => l.startsWith('第2出力'))` |

`specOf` は欄が無ければ `null` を返すので、**欄ごと消える壊れ方でも落ちます。**
失敗時のメッセージも `欄が無い` と `オプション欄: …` を出し分け、
「値が違う」と「欄が無い」を読み分けられるようにしてあります。

**空振り防止を同じ検査に入れてあります。** 「欄が出ない」だけを見る検査は、
仕様欄の描画ごと壊れても真になるので、
**同じ画面が別の欄を描いていること**を併せて見ます。

- `MS3749-A-O25（option なし）の②にオプションの欄が出ない` … `第1出力` の欄があることも見る
- `MS3749-A-D4/H の②に第2出力の欄が出ない` … `第1出力` の欄があること、かつ
  `MS3749-A-O25` 側には `第2出力` の欄があることも見る
- `②が銘板表記であることを名乗る` … `MS3749-A-O25` に対応表が出ることと
  `MS3749-A-D4/H` に出ないことを同時に見る

### 6-5. 同じPRで起きた、別の形の失敗（記録として）

**0件パネルの検査の前提が、データ追加で消えました。**
0件パネルは `MS3749-A-O22` で見ていましたが、PR #33 で `MS3749-A-O22/H` を登録したことで
この型式は候補1件になり、**0件パネルそのものが出なくなりました。**

対応は「落ちた検査を消さずに、0件になる型式へ**付け替える**」ことです。
付け替え先の `MS3749-A-D44/H` は、`MS3749-A-D4/H` と入力信号・第1出力が同一で
違うのは第2出力の有無だけ——文面が名乗る「第2出力を一方だけが持つ組は候補にしません」が
**まさに効いて0件になる型式**です。候補が1件でも出れば0件パネルは出ないので、
この検査は空振りしません。

## 8. ③の候補カードに電源電圧の差を出す（0〜7章より後の変更）

0〜7章と違い、この章は**実装を変えた記録**です。
`src/categories/insulation.mjs` の `detailPanels` に電源電圧のパネルを1枚足し、
`tools/smoke.mjs` に検査を3件足しました。②の仕様欄・`gate`・`data/**`・
コア（`src/core/`）・他カテゴリは変更していません。

### 8-1. 何が見えていなかったか

`MS3749-A-D45`（AC100〜240V）と `MS3749-D-D45`（DC24V）は互いの候補No.1です。
入力信号・第1出力・第2出力・外形寸法が同一で、どちらもオプションを持たないため、
4-1 のオプションのパネルも出ません。**違うのは電源電圧だけ**です。

それが③の画面に読める形で出ていませんでした。

- 基準機の `AC100〜240V` は③に一度も現れない（②の仕様欄にしかない）
- 候補の `DC24V` は、出典行（`evidence.specs.srcNote` の型式コードの読み下し）の
  本文の中にあるだけ

つまり③だけを見ると、この2件は差の読めない2枚のカードです。
4-1 が「`gate` に入れない項目は、違いを言わなければ『型式が違うだけの同じもの』として
受け取られる」と書いた形が、電源電圧でもそのまま起きていました。

### 8-2. 電源電圧が違う組は、絶縁変換器固有ではない（4カテゴリ 597組）

先に範囲を確かめました。**電源電圧が違う候補の組は、絶縁変換器だけの問題ではありません。**

| カテゴリ | `specs` のキー | 電源電圧が違う候補の組 |
|---|---|---|
| フォトスイッチ（photo） | `voltage` | 468組 |
| 近接スイッチ（proximity） | `voltage` | 124組 |
| 超音波センサ（ultrasonic） | `voltage` | 4組 |
| 絶縁変換器（insulation） | `powerSupply` | 1組 |
| **合計** | | **597組** |

数え方は「各カテゴリの全型式を基準にして候補を算出し、基準機と候補の両方が値を持ち、
かつ**文字列が違う**組を数える。向きの違いは同じ組として1つに数える」です。
再現するには次を実行します（`m.id` と `c.id` を並べ替えて重複を落とすので、
A→B と B→A は1組になります）。

```js
// node --input-type=module で実行。data/*.json を全部読んで候補を算出する
import { loadDevices, devicesOf } from './src/core/store.mjs';
import { getCategory } from './src/core/registry.mjs';
import { computeCompatibles } from './src/core/compat.mjs';
// カテゴリの登録（src/categories/*.mjs）を import してから loadDevices する
```

**残る6カテゴリは0組**ですが、0である理由は同じではありません。

| カテゴリ | 0組である理由 |
|---|---|
| 電磁接触器・電磁開閉器・サーマルリレー・サーボ | `specs` に電源電圧のキーが**無い**（電磁接触器・電磁開閉器・サーマルリレーは `coil` を持つが、これは操作コイルの仕様で別のキー） |
| インバータ | `specs.voltage` を持つ（`3相200V` / `単相200V` / `3相400V` / `3相575V` / `単相100V`）が、`gate` が電圧クラスと電源相数の一致を必要条件にしているため、**候補は必ず同じ値になる**（候補の組60件すべてで一致） |
| 特殊センサ | `specs.voltage` を持つ（12件中10件が `―`）。候補の組44件すべてで一致 |

**特殊センサの0組は「電源電圧が一致している」ことの証明ではありません。**
`―` という文字列を持つ10件どうしの組を、この数え方は「同じ」に数えます。
`―` は「該当なし」を文字列で持っている形なので、本来は値の不在です。
このカテゴリへ広げるなら、まずそこを読み直すのが先です。

### 8-3. それでも絶縁変換器だけに入れた理由

**他の3カテゴリの値が範囲を持ち、「違う＝使えない」と言えないためです。**

実データに現れる `specs.voltage` の値をそのまま並べます（重複を除いた全種）。

- フォト（7種）… `DC12-24V` / `DC10-36V` / `DC10-30V` / `AC/DC24-240V` /
  `AC48-240V/DC24-240V` / `AC100/200V` / `DC12-24V/AC・DC24-240V`
- 近接（13種）… `DC12-24V` / `DC10-30V` / `DC10-36V` / `DC20-70V` /
  `DC(2線)` / `DC(3線)` / `DC(3線+アース)` / `AC(2線)` / `AC(3線)` /
  `AC(2線+アース)` / `AC/DC(2線)` / `AC/DC(2線+アース)` / `⚠要確認`
- 超音波（2種）… `DC12-24V` / `DC24V`

**単一の値はほとんどありません。** 範囲（`DC10-36V`）、AC/DC の両対応
（`AC/DC24-240V`）、結線方式だけで電圧を書いていないもの（`DC(3線)`）、
値ですらないもの（`⚠要確認`）が同じキーに同居しています。

実際に候補として並ぶ組にも、**範囲が重なるもの**が入っています。
フォトの `DC10-36V` ⇔ `DC12-24V` は候補の組として現れますが、
`DC12-24V` の盤（DC24V）にはどちらも入ります。超音波の4組も
`DC12-24V` ⇔ `DC24V` で、DC24V の盤にはどちらも入ります。ここに
「電源電圧が違います」というパネルを出すと、**重なっている組にまで差を主張します。**

重なりを見るには文字列を範囲に解析する必要があります。それを書かなかったのは、
**解析が正しいことを検証できないため**です。`AC/DC(2線)` や
`DC12-24V/AC・DC24-240V` のような値は、範囲だけでなく結線方式や AC/DC の別まで
1つの文字列に入っており、これを解析する経路は「解析できないから一致とみなす」
（`CLAUDE.md` が禁じている形）か、逆に読み違えて差を主張するかのどちらかに倒れます。

絶縁変換器の `powerSupply` は違います。実データに現れる値は
**`AC100〜240V` と `DC24V` の2つだけ**で、範囲を持ちません。
2値のうちどちらであるかは型式コードの1文字（`A` / `D`）で決まり、
`evidence.specs.srcNote` の読み下しにも `A＝AC100〜240V` と入っています。
**文字列が違えば別の電源である**と、解析なしで言えます。

他カテゴリへ広げるなら、先に「範囲をどう読むか」を決めて、その解析に検査を付けるのが順です。
この章はそこまで決めていません。

### 8-4. 「使用できない」と断定しない理由

パネルの本文はこうです。

> この候補: DC24V
> 基準 MS3749-A-D45: AC100〜240V
> 電源電圧が違います。盤に来ている電源を確認してください。
> 電源電圧は互換判定に使っていません。一致は候補の条件ではありません。

**「使用できない」とは書いていません。** 理由は2つあります。

1. **コードが知っているのは文字列が違うことだけ**で、AC と DC の区別はしていません。
   `powerSupply` は比較にしか使っておらず、値の意味を読んでいません。
   将来この値に範囲を持つものが入れば（8-3 の他カテゴリがすでにそうです）、
   断定はそのまま嘘になります。
2. **アプリは盤に何が来ているかを知りません**（→ 8-5）。
   DC24V の機器でも、盤に DC24V が来ていれば使えます。

これは段4で「容量が足りない機種も含みます」と書かなかったのと同じ原則です
（`docs/design-c-legacy-inverters.md` 6-10 節：アプリが知っているのは登録値であって
実際の負荷電流ではない。「足りない」と断定すると、データが支えていないことを
画面が主張することになる）。書けるのは**事実（両方の値）**と
**現場で確かめること（盤に来ている電源）**までです。

4-1 のオプションのパネルと同じく、**判定に使っていない旨も本文に書きます。**
書かないと、パネルが出ている＝判定で見た、と読めます。

**枠の色（`tone`）は `warn`（橙）**です。これは依頼者の判断で、
このカテゴリで最も目立つ表示にする、という指定によります。
オプションのパネルが候補側にだけ付いているときの `info`（青）より強い扱いになります。

**パネルが2枚出る場合の並び順は 電源電圧 → オプション。**
電源電圧もオプションも違う組は現在のデータには無い（8-1 のとおり唯一の組は
どちらもオプションを持たない）ため、**並び順を固定する検査は作っていません**
（対象0件のまま「PASS」と出る検査になる。`CLAUDE.md`）。順を決めた理由は2つです。

1. 電源電圧は**盤側**の条件で、オプション（コーティング・センサ供給電源）は
   機器と接続先の条件。盤に電源が来ていなければ、他をどれだけ見てもその候補は動かない
2. ②の仕様欄（`summary`）も 電源電圧 → オプション の順で描いている。
   ②と③で並びが割れると、同じ2項目を画面ごとに違う順で読むことになる

**検査は「そのカードのパネル」から読みます。** 画面全体の文字列で見ないのは6章の理由と
同じで、このカテゴリは `srcNote` に型式コードの読み下しを書くため、
`DC24V` も `AC100〜240V` も出典行に現れるからです。**パネルを消しても
画面全体の検索では通ってしまいます。** さらに、全カードのパネルを1本の配列にすると
「どのカードに出たか」を言えないので、カードごとに見出し（`.cmp b`）と
本文（`.cmp span`）へ分けて拾い、そのカードのパネルだけを見ます。

### 8-5. 電源電圧を `gate` に入れない理由（7章への答え）

**まず事実として、7章にこの項目はありません。**
7章の9項目は 3888通り／出典2系統の検査／極性反転スイッチの検査／Rev の差／在庫数／
オプション表7種／主スペックの暫定／`/D` の代替可否／実測値の再現手順で、
電源電圧と `gate` の関係を挙げた項目は 0〜7章のどこにもありません
（`grep -n "電源" docs/design-insulation-converter.md` で確認）。
依頼にある「7章の『電源電圧を gate に入れない判断を記録した箇所が無い』」は、
文書の現物と一致していません。それでも**問い自体には答えが要る**ので、ここに書きます。

**入れない理由は、盤に来ている電源をアプリが知らないためです。**

`gate` を通らなければ候補として並びません。電源電圧の一致を `gate` に入れると、
`MS3749-A-D45` の③から `MS3749-D-D45` が消えます。しかしそれは
「使えないから消えた」ではありません。**DC24V の機器でも、盤に DC24V が来ていれば使えます。**
盤に何が来ているかはアプリの持っているデータの外にあり、
`gate(a, m, ctx)` が受け取るのは基準機・候補・UIの絞り込み条件だけです。

判定から落とすと、現場は画面上その候補の存在を知る手段を失います。
表示に出せば、値の両方が読めたうえで**現場が盤を見て決められます。**
「アプリが決められないことは、決めずに材料を出す」——これは 4-1 が
オプションについて書いたのと同じ扱いです。

なお、`gate` に入れないという判断は、この章より前から実装としてはそうなっていました
（`gate` は入力信号・第1出力・第2出力しか見ていません）。
**理由が書かれていなかった**ので、ここが初出の記録になります。

### 8-6. 渡辺電機工業 WVP / WGP の追加で下した判断（7章 10〜15 への回答）

9章は PR #40〜#43 の実装・検査・データから読み取れることを書いています。
本節は、そこから読み取れなかった判断に、**判断した本人（依頼者とレビュー側）**が

#### 8-6-1. WVP の電源コード表の全体（7章10）

**6種です。** 資料（渡辺電機工業 仕様書 `WVP-DS / DZ` および `WVP-DE`、
いずれも資料番号 2206A-06）の型式コード表から。

| コード | WVP | WGP |
|:--:|---|---|
| `1` | AC100V±10%（50/60Hz） | AC100〜120V±10%（50/60Hz） |
| `2` | AC200V±10%（50/60Hz） | AC200〜240V±10%（50/60Hz） |
| `3` | DC24V±10% | DC24V±10% |
| `4` | AC110V±10%（50/60Hz） | **存在しない** |
| `5` | AC220V±10%（50/60Hz） | **存在しない** |
| `6` | DC110V±10% | **存在しない** |
| `8` | **存在しない** | DC110V±10% |

WGP の資料には「DC48V電源をご希望の場合はお問い合わせください」との注記があります。
WVP の資料に同じ注記はありません。

**この表はリポジトリに入っていません。** 資料はレビュー側が依頼者から
スクリーンショットで受け取ったもので、URL も持っていません（7章 14 の `srcUrl` 不在と同根）。
したがって 9-1 が書くとおり、**表の流用は検査では捕まりません。**

#### 8-6-2. 電源電圧を判定に使わない理由（依頼者の判断）

**電源の仮接続で対応できるからです。**

盤に来ている電源が違っても、現場では仮に電源を引いて動かすことができます。
復旧を急ぐ場面では、それが現実的な手段になります。

**アプリは盤に何が来ているかを知りません。** DC24V の機器でも、盤に DC24V が来ていれば
そのまま使えます。判定で落とすと、**使える機器を候補から消します。**

だから判定には使わず、**違うことを橙のパネルで明示する**形にしました（9-4）。

#### 8-6-3. 外形寸法を判定に使わない理由（依頼者の判断）

**配線変更で対応できるからです。**

WGP は 105×25.6×136.5mm、WVP は 97×51×126mm で、**幅が約半分**です。
盤の中で差し替えると取付スペースが余るか足りないかになりますが、
DINレール取付なので物理的には付きます。

**ただし端子配列が違います。**

| 端子 | WGP | WVP |
|:--:|---|---|
| 1-2 | INPUT | OUTPUT |
| 3-4 | NC | INPUT |
| 5-6 | OUTPUT | NC |
| 7-8 | POWER | POWER |

**入力と出力が入れ替わっています。** そのまま挿せば入出力が逆になります。
配線をやり直す必要がありますが、**それは現場でできることです。**

したがって候補には出し、**寸法が違うことと、端子配列の確認が要ることを画面で示す**
形にしました。依頼者の言葉では「配線変更が要ることを画面で明示」です。

#### 8-6-4. 端子配列をデータに持たない理由（依頼者の判断）

**持ちません。** 資料に表があるので登録はできますが、依頼者が不要と判断しました。

代わりに、外形寸法のパネルの文面で
「取付スペースと、端子配列が同じかを確認してください」と促します（9-4-3）。

**「端子配列も異なります」と断定しない**のは、レビュー側の判断です。
WGP と WVP は現に違いますが、**将来 `WSP` や `WAP` を入れたとき同じかもしれません。**
資料で確認していないことを断定すると嘘になります。
段4で「容量不足」と断定しなかったのと同じ原則
（`docs/design-c-legacy-inverters.md` 6-10 節）。

#### 8-6-5. 応答時間を判定に使い、非対称にした理由（依頼者の判断）

**「速い機器が設置された設計意図を、後から解析するのは難しい」からです。**

これが依頼者の言葉です。25ms の機器が付いている回路に、なぜ25ms が選ばれたのかは
図面を追わないと分かりません。**そこまで遡らずに遅い側へ落とすと、
設計意図を壊す置換えを勧めることになります。**

一方、**速い側へ替えて困ることはありません。** だから

```
基準より速い、または同じ  → 候補にする
基準より遅い              → 候補にしない
```

としました。判定は意図的に非対称です（9-2）。

**当初レビュー側は「候補には出すが遅いことを明示する」を推しました。**
アプリは「その用途に何msが必要か」を知らないので、外すと使える機器を消す、という理由です。
依頼者がそれを採らず、上の理由で「外す」を選びました。

**この判断は覆せます。** 覆すなら、`WGP-DE-25R-1` の③が0件になっている現状
（同じ入出力の遅い機器が3件あるのに全部外れる）を、現場が困ると感じたときです。

#### 8-6-6. 特注コード（入力 `99` ・出力 `S`）を将来どう扱うか（7章15）

**銘板でレンジが確定すれば登録できます。** そのときは通常の型式として扱います。

`99` は「上記以外　お問い合わせください」で、注文時に範囲内のレンジを個別に指定します。
電圧入力なら ±300V 以内・スパン 10mV〜600V、電流入力なら ±20mA・スパン 10μA〜40mA
（WVP。WGP は電流入力 ±50mA・スパン 10μA〜100mA）。

**型式からは決まりませんが、現物の銘板には印字されています。**
MS3749 の銘板に `IN OPN.C.` と印字されていたのと同じで、WVP / WGP の前面にも
`INPUT 1-5V` `OUTPUT 4-20mA` のような表示があります（資料の製品写真で確認できます）。

したがって**予備品棚の現物を撮れば、レンジが確定して登録できます。**
現時点でそれをしていないのは、手間に見合うかを判断していないためです。

**登録しなかった8件の綴り**（7章13）は次のとおりです。

```
WVP-DE-99R-1   WVP-DE-99R-4   WVP-DE-99S-1   WVP-DE-99S-3
WVP-DE-99W-3   WVP-DS-25S-1   WVP-DS-99A-5   WVP-DZ-99A-3
```

`WVP-DS-25S-1` は入力 `25`（DC±10V）が確定していますが、**出力 `S` が特注**なので対象です。

あわせて WGP で登録しなかった2件は `WGP-DS-25S-1`（出力 `S`）と
`WGP-DS-99A-1`（入力 `99`）です。

**`WVP-DZ-99A-3` は、予備品リストに2通りの記載がありました。**

| リストの画面 | 入力の記載 |
|---|---|
| 1枚目 | 0〜40mV |
| 2枚目 | 0〜250V |

同じ型式で、**別の個体である可能性が高い。** これが「値として持つと `99` どうしが
すべて一致してしまう」という 9-3 の懸念を、実データで裏付けた例です。

## 9. 渡辺電機工業 WVP / WGP の追加（PR #40〜#43）で決まった事項

0〜7章と同じく、**この章は読み取りだけの記録**です。この章を書くにあたって
コード・検査・データは1文字も変更していません。根拠は `origin/main`（`73fbab5`）に
入っている実装・検査・データと、PR #40〜#43 のコミットメッセージだけです
（PR #42 はマージされていないので根拠にしていません。0-1 の注）。

### 9-1. 型式コード表はシリーズごとに違う（表を流用しないこと）

**この章でいちばん重要な事項です。**

WVP と WGP は**同じメーカー（渡辺電機工業）で、機種名の綴りも同じ**です。
どちらにも `DS`（アイソレータ）と `DE`（高速アイソレータ）があり、
入力・出力の表は共通です——`insulation.mjs` は「**入力・出力の表は WVP-DS / DZ と同一**。
入力24種・出力15種・入力抵抗・許容負荷抵抗は一致する」と書いており、
PR #43 のコミットメッセージは、既登録 WVP 39件の入力コード・出力コードと
**64箇所を照合して全一致**だったと書いています。

**それでも電源コードの表は違います。**

| | 資料の電源コード表（`insulation.mjs` の記述） |
|---|---|
| WGP | `1`＝AC100〜120V ／ `2`＝AC200〜240V ／ `3`＝DC24V ／ `8`＝DC110V の**4種だけ**。**`4` `5` `6` は存在しない** |
| WVP | `1`＝AC100V ／ `4`＝AC110V ／ `5`＝AC220V ／ `6`＝DC110V（コメントが名指ししているのはこの4つ） |

**DC110V のコードは WGP が `8`、WVP が `6`** です。`insulation.mjs` は
「WVP の表をそのまま当てると、**同じ末尾1桁が別の電源になる**」と書いています。

MS3749 はさらに別の表を持ちます。電源は型式コードの1文字で決まり、
`A`＝AC100〜240V ／ `D`＝DC24V です（`evidence.specs.srcNote` の読み下し。8-3）。
**3系列が3つの別々の表を持っている**ことになります。

**データから確認できる範囲。** 62件の `specs.powerSupply` を系列ごとに数えました。

| 系列 | 件数 | `powerSupply` に現れる値（件数） |
|---|---|---|
| MS3749 | 14 | `AC100〜240V` 12 ／ `DC24V` 2 |
| WVP | 39 | `AC100V` 21 ／ `AC110V` 7 ／ `DC24V` 5 ／ `AC220V` 4 ／ `AC200V` 2 |
| WGP | 9 | `AC100〜120V` 7 ／ `DC24V` 2 |

型式の末尾1桁と、データ上の値の対応も数えました（**どのコードも値は1つに定まります**）。

| 系列 | `1` | `2` | `3` | `4` | `5` |
|---|---|---|---|---|---|
| WVP | `AC100V` | `AC200V` | `DC24V` | `AC110V` | `AC220V` |
| WGP | `AC100〜120V` | （データに無し） | `DC24V` | （表に無し） | （表に無し） |

**同じ末尾 `1` が、WVP では `AC100V`、WGP では `AC100〜120V`** です。
データに現れる範囲だけを見ても、末尾1桁は**系列を見なければ読めません**。

データに現れないコードもあります。WVP の `6`（DC110V）、WGP の `2`（AC200〜240V）と
`8`（DC110V）は `insulation.mjs` のコメントにあるだけで、**実データには1件もありません**。
また WVP のコメントは `2`＝AC200V・`3`＝DC24V を名指ししていませんが、
**実データには両方あります**（上の表）。つまり**コメントの表は WVP については一部だけ**で、
WVP の電源コード表の全体はリポジトリから読み取れません（→ 7章）。

**表を流用すると、存在しない電源のデータが入ります。そして検査では捕まりません。**

理由は、**型式コード表が資料にしかなく、資料がリポジトリに無い**ためです。
機械的に照合する相手がありません。具体的には次のとおりです。

- `tools/verify-data.mjs` に `powerSupply` の値を見る検査はありません
  （`grep` で確認：`verify-data.mjs` に `powerSupply` は1度も現れない）。
  許可値のリストを持たないのは `option` の `code` の許可値を書かないのと同じ形で、
  **データに無いものの文言を検査側で二重管理しない**という判断です（2-2 / 4-6）
- `gate` は `powerSupply` を見ません（8-5）。判定が通るかどうかも変わりません
- `smoke` の電源電圧のパネルの検査（`MS3749-A-D45 の③に電源電圧のパネルが出て、…`
  ほか）は、**`data/insulation.json` に書かれた値がそのまま画面に出ていること**を
  見ます。値そのものが取り違えであっても通ります

`insulation.mjs` が挙げている唯一の歯止めは人が読む形のものです——
「`data/insulation.json` の `srcNote` は型式コードの読み下しに電源の値まで書いてあるので、
取り違えると画面で食い違う」。**読み下しと値を突き合わせれば人は気づけますが、
それを機械的に照合する検査はありません**（→ 7章）。

**出力コードの表も系列で違います。** `insulation.mjs` の記述から:

- `U`（DC±10mA・500Ω以下）と `W`（DC±20mA・250Ω以下）は **`DE` の表にしかなく、
  `DS` / `DZ` では選べない**
- `S`（上記以外）の許容負荷も、`DS` / `DZ` が「電流20mA以下／電圧10V以下」、
  `DE` が「電流50mA以下／電圧10V以下」で違う
- いま登録している WVP 39件に `U` / `W` / `S` の型式は1件もないので、
  **この違いはデータには現れない**。`insulation.mjs` は
  「**現れないからこそ、後から型式を足すときに `DS` / `DZ` の表へ流用しないこと**」と
  書いています

ゼロ・スパン調整範囲も違います（WGP ±10%fs 15回転 ／ WVP ±20%fs 25回転）が、
判定にも表示にも使わないので登録していません。外形寸法の違いは 9-4 にあります。

### 9-2. 応答時間の判定

**`responseUs` を持つ型式と持たない型式があります。**

| | 件数 | 応答の速さの語り方 |
|---|---|---|
| WVP 39件・WGP 9件 | **48件が `responseUs` を持つ** | 応答時間（μs の数値） |
| MS3749 14件 | **持たない（キーごと不在）** | 最大出力周波数（`output1MaxFreqHz` / `output2MaxFreqHz`） |

`insulation.mjs` は、MS3749 が応答時間を持たないのは**性質の違う量だから**であって
データの欠落ではない、と書いています。2つを同じキーに寄せていません。

**実データの `responseUs` の全件集計**（62件を走査）。

| 値（μs） | `formatResponse` の表示 | 件数 | 内訳 |
|---|---|---|---|
| 120 | `約120μs` | 2 | WGP-DE 2 |
| 500 | `約500μs` | 10 | WVP-DE 10 |
| 25000 | `約25ms` | 32 | WVP-DS 25 ／ WGP-DS 7 |
| 200000 | `約200ms` | 4 | WVP-DZ 4 |
| （キーごと不在） | — | 14 | MS3749 14 |
| **合計** | | **62** | |

4通りの値であることは、検査名
`応答時間を持つ型式が4通りの値を持つ` が**実数で**固定しています（5-3）。
表示が `1000μs` を境に μs と ms で分かれるのは、**資料の表記に合わせる**ためです
（資料は4機種とも「約120μs」「約500μs」「約25ms」「約200ms」と書いている。
`formatResponse` の JSDoc）。「約」を落とさないのも同じ理由で、
25000 は 25ms ちょうどを測った値ではないからです。

**判定は「基準以下（同じか速い）」です。** `responseWithin(a, m)` は候補 `a` と
基準 `m` を取り、次のように振る舞います。

| 状況 | 返り値 | 意味 |
|---|---|---|
| 両方とも持たない（MS3749 どうし） | `true` | この量で語らない系列なので**判定材料にしない** |
| 片方だけが持つ | `false` | 性質の違う量なので「以下である」と言えない（`signalMatch` と同じ扱い） |
| 両方が持つ | `a <= m` | **同じか速いものだけを候補にする** |

**したがって意図的に非対称です。** `insulation.mjs` は「この判定だけが意図的に非対称
（依頼者の判断）」と明記し、理由をこう書いています——
**速い機器が設置された設計の意図を後から解析するのは難しく、遅い側に落とすリスクを
取らない。** 速い側へ替えて困る設計もあり得るが、それは現物と図面を見れば分かる。
遅い側へ替えたときの不具合（追従の遅れ）は動かしてみるまで出ないことがある。

帰結として、**最速の値を持つ型式は同じ入力・出力の候補が0件になります。**
WGP-DE の 120μs は全62件で最速なので `WGP-DE-25R-1` の③は0件です。
これは登録の欠落ではなく判定が働いた結果で、逆向き（`WVP-DS-25R-1` を基準）にすれば
`WGP-DE-25R-1` は候補に出ます。`smoke` はこの両方向を見ています（5-2）。

**既存の `test-compat` の対称性検査は、絶縁変換器を対象にしていません。**
`test-compat` の2件（`候補の関係が対称（A→B なら B→A。後継品リンクを除く）` と
`接触器・電磁開閉器でも候補の関係が対称（A→B なら B→A。後継品リンクを除く）`）は
インバータ・電磁接触器・電磁開閉器を対象にしていて、絶縁変換器を含みません
（`test-compat.mjs` 冒頭の JSDoc は、この対称性を**窓（`withinWindow`）を使う
カテゴリの性質**として宣言しています）。

**掛からないことと、正しい向きに非対称であることは別の話です。**
`insulation.mjs` はこの点をはっきり書いています——掛からないだけでは、
`responseWithin` が `Math.max` のような対称化に書き換えられても誰も落ちない。

**非対称であることを固定しているのは `tools/test-insulation-response.mjs` です。**
PR #41（`b89c281`）で新設された専用ファイルで、`npm run check` に組み込まれています。
検査名の一覧は 5-3 にあります。要点は3つです。

1. 62件を全件走査して、**非対称な辺が実在する**ことと、
   **その辺がすべて「候補のほうが速い」向き**であることを見る
2. 入力・出力が一致しても**遅い側は候補にならない**辺が実在することを見る
3. **対称化した `gate` を実際に組み立てて**非対称な辺が0本になることまで確かめる
   （`対称化（Math.max 相当）を当てると非対称な辺が0本になる（この検査が空振りでない）`）

別ファイルにした理由も書かれています。`test-compat.mjs` は名前どおり「対称」を
宣言するファイルで、**そこに反対の性質を同居させると検査名が実態を語らなくなる**ため。
`smoke` に足さなかったのは、画面を歩く形では代表の数件しか見られず、
**対称化は検査が拾っていない組から静かに壊れる**ためです。

`gate` の必要条件が4つになったので、0件パネルの文面も追随しています
（`絶縁変換器の0件パネルが必要条件（入力信号・出力信号・第2出力・応答時間）を名乗る`）。
`emptyNote` の JSDoc は「`gate` を変えたらこの文面も追随させること。
応答時間の1文は `responseWithin` を足したときに増やした」と書いています。

### 9-3. 特注コード（入力 `99`・出力 `S`）を登録しないこと

渡辺電機工業の型式コード表には、入力 `99`「上記以外（電流入力 ±20mA
スパン10μA〜40mA／電圧入力 ±300V スパン10mV〜600V）」と 出力 `S`「上記以外」が
あります（`verify-data.mjs` の JSDoc）。**これを使う型式は登録していません。**

**理由はコードから読み取れます。**

1. **実際のレンジが型式から決まりません。** 同じ `WVP-DZ-99A-3` について、
   社内リストの記載が **0〜40mV と 0〜250V の2通り**ありました
   （`insulation.mjs` と `verify-data.mjs` が同じ例を挙げています）
2. **値としてそのまま登録すると、`signalMatch` が `99` どうしをすべて「一致」と
   判定します。** 結果として **0〜40mV の機器と 0〜250V の機器が互換だと画面に出ます**
3. これは `CLAUDE.md` の「**『解析できないから一致とみなす』経路を作らない**」に
   あたります。`insulation.mjs` はこの規約を名指しで引いています

`insulation.mjs`・`verify-data.mjs` とも「**依頼者の判断**」と明記しています。

**件数。** WVP 側は PR #40・#41 のコミットメッセージが「§8-3 の8件（入力コード 99
または 出力コード S）」と書いています。WGP 側は特注2件（`WGP-DS-25S-1`・
`WGP-DS-99A-1`）です。ただし**型式の綴りが読めるのは4件だけ**で
（`WVP-DE-99W-3`・`WVP-DZ-99A-3`・`WGP-DS-25S-1`・`WGP-DS-99A-1`）、
残りの型式名はリポジトリに残っていません（→ 7章）。

**この点を守っている検査（`verify-data`）**

- `入力信号・出力信号に「上記以外」の特注コードが無い`
  … `specs.inputSignal` と `specs.outputSignal` の値に「上記以外」という文字列が
  含まれないことを見ます。**キーごとに保有0件を失敗にしてあります**
  （対象0件のまま「PASS」と出さないため。`verify-legacy` 検査1 が塞いだ穴と同じ形）

**検査にした理由も書かれています。** 「**将来リストから機械的に流し込んだときに
気づけるようにする**ため。人が1件ずつ見て弾く約束は、件数が増えれば必ず漏れる」
（`verify-data.mjs` の JSDoc）。

**読み取れないこと。** 在庫数（4-4）のように「**別の形で持つ可能性を残した保留**」
という書き方はされておらず、**再検討の条件も書かれていません。**
「登録しない」とだけ書かれています。特注を（レンジを持たない印だけの形などで）
将来登録する余地があるかどうかは、この文書からは読み取れません（→ 7章）。

### 9-4. 表示の約束（電源電圧のパネルと外形寸法のパネル）

③の候補カードに出るカテゴリ固有パネルは3枚あります
（`detailPanels` が `powerSupplyPanel` / `optionPanel` / `dimsPanel` を並べます）。
このうち**外形寸法のパネル（`dimsPanel`）が PR #43 で新設**されました。

#### 9-4-1. 電源電圧のパネルと外形寸法のパネルの違い

| | 電源電圧（`powerSupplyPanel`・PR #36） | 外形寸法（`dimsPanel`・PR #43） |
|---|---|---|
| 出す条件 | 両方が `powerSupply` を持ち、**文字列が違う**とき | 両方が `dims` を持ち、**3辺のどれかが違う**とき |
| 枠の色（`tone`） | `warn`（橙） | `warn`（橙） |
| 値の書式 | `specs.powerSupply` の文字列をそのまま | `formatDims` が資料の書き方 `105(H)×25.6(W)×136.5(D)mm` に整える（並びは H → W → D） |
| 現場に促すこと | 盤に来ている電源を確認すること | 取付スペースと、端子配列が同じかを確認すること |
| **判定に使っていない旨の文** | **「電源電圧は互換判定に使っていません。一致は候補の条件ではありません。」** | **「外形寸法は候補にするかどうかの判定には使っていません（候補の並び順には使います）。」** |

**枠の色が同じ `warn`（橙）である理由**も、両方に同じ形で書かれています——
盤に来ている電源も盤の取付スペースも**現場が変えられないことが多く、
気づかずに手配すると盤側の工事に波及する**（どちらも依頼者の判断）。

#### 9-4-2. 「互換判定に使っていません」と「候補にするかどうかの判定には使っていません（候補の並び順には使います）」の書き分け

**書き分けているのは、事実が違うからです。**

- **電源電圧は、候補の可否にも並び順にも一切使われません。** `gate` は
  `powerSupply` を見ず（8-5）、`rank` の4段（`mountingMatch` → `sameMaker` →
  `evidenceRank` → `ascending(a.diff, b.diff)`）にも `powerSupply` は入っていません
- **外形寸法は、`gate` には使いませんが並び順には使っています。**
  `rank` の最後の段が `ascending(a.diff, b.diff)` で、この `diff` は
  `src/core/compat.mjs` が `dimDiff(a.dims, m.dims)` で作る**寸法差**です
  （カード右上の `dim-verdict` が `差 Σ43.9mm` と出すのと同じ値）

`dimsPanel` の JSDoc はこう書いています——**「電源電圧の文面をそのまま写すと
『使っていません』が事実と食い違うので、分けて書く」。**

**この書き分けを守っている検査はありません。** `grep` で確認したところ、
「互換判定に使っていません」と「候補の並び順には使います」のどちらの文言も
**`src/categories/insulation.mjs` にしか現れず**、`tools/smoke.mjs` にも
他のどの検査にもありません。外形寸法のパネルに電源電圧の文面を写す壊し方をしても、
落ちる検査はありません（→ 7章）。

#### 9-4-3. 外形寸法のパネルが「端子配列も異なります」と断定しないこと

**WGP と WVP は現に端子配列が違います。** `insulation.mjs` は
「WGP は 1-2 が INPUT・5-6 が OUTPUT で、WVP（1-2 が OUTPUT・3-4 が INPUT）とは
入力と出力が入れ替わっている」と書いており、「寸法が合ってもそのまま挿せば
入出力が逆になる」とまで書いています。

**それでも画面で断定しません。** 理由は2つです。

1. **端子配列をデータに持っていません**（依頼者の判断）。このコードが知っているのは
   `dims` の3辺が違うことだけで、寸法の差から端子配列の差を言うのは
   **資料で確認していないことを画面が主張する**ことになります
2. 将来、**寸法が違っても端子配列が同じシリーズ**（`insulation.mjs` は渡辺電機工業の
   `WSP` を例に挙げています）が入れば、**断定はそのまま嘘になります**

書けるのは「寸法が違う」「取付スペースと、端子配列が同じかを確認すること」までです。
段4で「容量が足りない機種も含みます」と書かなかったのと同じ原則で
（`docs/design-c-legacy-inverters.md` 6-10 節）、電源電圧のパネルが
「使用できない」と書かないのと同じ形です（8-4）。

**この点を守っている検査（`smoke`）**

- `外形寸法のパネルが「端子配列も異なります」と断定しない（データに持っていない）`
  … 「端子配列も異なります」「端子配列が異なります」「端子配列も違います」
  「端子配列が違います」の**4通りの言い回し**が本文に出ないことを見ます。
  空振り防止に、**同じカードにパネルが出ていること自体**も併せて見ます
  （パネルが消えれば「断定が無い」は真になってしまうため）

#### 9-4-4. パネルの並び順

**電源電圧 → オプション → 外形寸法** です（`detailPanels` の配列順）。
`insulation.mjs` は理由を3つ挙げています。

1. **電源電圧は盤側の条件**で、オプション（コーティング・センサ供給電源）は
   機器と接続先の条件。**盤に電源が来ていなければ、他をどれだけ見てもその候補は
   動かない。** 先に読ませるのは判断の順に合わせるため
2. **②の画面も同じ順**で描く——仕様欄（… → 電源電圧 → オプション）→ 外形寸法図
   （`src/core/app.mjs`）。②と③で並びが割れると、同じ項目を画面ごとに違う順で読むことになる
3. **外形寸法の差は、カード右上の `dim-verdict` でカードの先頭にすでに出ている。**
   パネルはその読み下しなので、カードのどこにも出ていない差（電源電圧・オプション）より
   後ろでよい

**2枚並ぶ組は実在します。** `WGP-DS-15P-1`（AC100〜120V・105×25.6×136.5mm）と
`WVP-DS-15P-4`（AC110V・97×51×126mm）は電源電圧も外形寸法も違います。

実測しました（62件から候補を全件算出。`computeCompatibles` を全件に走らせた結果）。

| | 本数 |
|---|---|
| 候補の辺（向きを区別した合計） | 79 |
| シリーズをまたぐ辺 | 30（WVP → WGP 17 ／ WGP → WVP 13） |
| 外形寸法のパネルが出る辺 | 30 |
| 電源電圧のパネルが出る辺 | 68 |
| **両方のパネルが出る辺** | **30** |

**外形寸法のパネルが出る30本は、全部が電源電圧のパネルも出ます。**
`insulation.mjs` は理由をこう書いています——WGP の電源コードは WVP と表が違うので
（9-1）、**シリーズをまたぐ候補は電源電圧の文字列も必ず違う値になる**ため。

**この点を守っている検査（`smoke`）**

- `WVP-DS-15P-4 の候補カードに電源電圧と外形寸法のパネルが 電源電圧 → 外形寸法 の順で2枚出る`
  … **見出しの配列をそのまま突き合わせる**ので、片方が消えても順が入れ替わっても落ちます

**オプションと外形寸法が同時に出る組は、現在のデータにはありません。**
`option` を持つのは MS3749 の9件だけで、MS3749 は WVP / WGP と互いの候補にならず
（`gate` の出力信号のキーの条件）、MS3749 どうしは全件が同じ寸法（86×29×125mm・
実データで確認）だからです。3枚並ぶ組も同じ理由でありません。
**対象が0件なので、その並びを固定する検査は作っていません**
（0件のまま「PASS」と出る検査になる。`CLAUDE.md`）。順と理由をコードに残してあるのは
そのためだ、と `detailPanels` の JSDoc は書いています。

PR #36 の時点では2枚並ぶ組が1組も無く、並び順を検査で固定できませんでした
（8-4 に同じことが書いてあります）。WGP を足して初めて固定できるようになりました。

#### 9-4-5. `dims` を持たない場合の扱い

**片方でも `dims` を持たなければ、パネルを出しません。**

- **理由** … 基準機の寸法とこの候補の寸法の**両方を出すのがこのパネルの用件**なので、
  片側が欠けたまま出すと**片方しか言えない枠**になります。不在を「同じ」にも「違う」にも
  倒さないのは `signalMatch`・`powerSupplyPanel` と同じ扱いです
- **現在の62件は全件が `dims` を持ちます**（実データで確認：62件）。
  **この経路はいま一度も通りません**
- 寸法が読めないこと自体は画面から消えません。寸法を持たない候補には
  カード右上の `dim-verdict` が「寸法未確認」を出し、②には
  「外形寸法は未確認のため図を表示しません」が出ます（`src/core/ui.mjs` /
  `src/core/app.mjs`）

**`evidence.dims` の状態（`verified` かどうか）は見ません。** 理由は2つです。

1. 状態が `verified` でない候補には、カードがすでに「要確認」バッジ（`statusBadges`）と
   「寸法未確認」（`dim-verdict`）で断りを出しています。**同じことをパネルで
   二重に言っても情報が増えません**
2. **現在の62件は `evidence.dims.state` が全件 `verified`**（実データで確認）なので、
   状態を条件に足すと**一度も通らない分岐**になります。正しさを検査で固定できない条件を
   先回りで書かない（`CLAUDE.md`「対象が0件でも『全項目PASS』と出る検査を作らない」と
   同じ趣旨）

**「片方でも `dims` を持たなければ出さない」経路を守っている検査はありません。**
62件が全件 `dims` を持つので**対象が0件**だからです。同じ理由で、
`powerSupplyPanel` の同じ経路（片方でも `powerSupply` を持たなければ出さない）にも
検査がありません（62件とも `powerSupply` を持つ）。→ 7章

#### 9-4-6. 表示の約束を守っている検査（`smoke`・検査名）
